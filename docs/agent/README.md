# Agent Runtime Docs

This folder contains per-task run artifacts generated by the pipeline agents.

The pipeline is **stack-agnostic**. A unit of work may be a Jira story, a feature description, a free-form user request, or a RAG-derived task (declared as `input_source` in `plan-input.md`). The target may be backend, frontend, mobile, infra, or polyglot.

Throughout the docs `{story_id}` is an identifier placeholder — it can be a Jira key (`ACME-1421`), a feature slug (`user-profile-avatar-upload`), a request slug (`rag-2026-04-cleanup`), or any stable id. Use what the operator supplies; do not invent.

## Working mode
- Start with Plan output, then invoke `ai-pipeline-rgr-orchestrator` only.
- Stage agents are not direct entrypoints.
- Use templates under `docs/agent/templates/` for run docs.
- Every run is isolated in a git worktree at `.agent-runs/{story_id}` on branch `story/{story_id}`.

## Structure
```
docs/agent/
├── current-run.md          # Active run pointer
├── decision-index.md       # Compact links to task decision logs + final verdicts
├── learnings.md            # Cross-task operational learnings register (tag-filtered)
├── runs/
│   └── {story_id}/         # identifier: Jira key, feature slug, request slug, …
│       ├── run-context.md         # Replace-in-place state
│       ├── plan-input.md          # Write-once
│       ├── brainstorm.md          # Write-once — declarative SCs
│       ├── detailed-plan.md       # Replace-in-place pre-RED; locked once RED starts
│       ├── handoff.md             # Append-only; one section per stage
│       ├── quality-gates.md       # Replace-in-place — final verdict
│       ├── decision-log.md        # Append-only
│       └── error-report.md        # Create-on-failure only
└── archive/
    └── {yyyy-mm}/                 # Closed runs older than current release
```

## Rules
- Per story, create a folder under `runs/{story_id}/`.
- Keep cross-story operational memory in `learnings.md` only.
- Archive closed runs periodically to `archive/{yyyy-mm}/`.
- Treat `handoff.md` and `decision-log.md` as append-only (narrow resume exception — see orchestrator).
- Treat `run-context.md` and `quality-gates.md` as replace-in-place state docs.
- Treat `brainstorm.md` and `plan-input.md` as write-once.
- All agents read `learnings.md` at run start with tag filtering matching the story scope. Stage agents append `candidate` learnings; `ai-pipeline-quality-gate` curates statuses.

## Mutation policy

| File | Policy | Notes |
| --- | --- | --- |
| `run-context.md` | Replace-in-place | Controlled state document |
| `plan-input.md` | Write-once | Preserve original planning intent |
| `brainstorm.md` | Write-once | Locked before RED starts |
| `detailed-plan.md` | Replace-in-place (pre-RED only) | Lock once RED starts |
| `handoff.md` | Append-only | Stage sections: `BRAINSTORM`, `RED`, `GREEN`, `REFACTOR`, `VERIFY` |
| `decision-log.md` | Append-only | Timestamp every entry |
| `quality-gates.md` | Replace-in-place | Final verdict document |
| `error-report.md` | Create-on-failure | No file on success |
| `learnings.md` | Append rows for candidates; curated updates by quality gate | Tag-filtered register with `candidate/active/deprecated/conflicted` lifecycle |

| Agent | Writes to |

| `ai-pipeline-brainstorm` | `brainstorm.md`, `handoff.md` (BRAINSTORM section), `decision-log.md`, `learnings.md` (candidate rows) |
| `ai-pipeline-red-test` | `handoff.md` (RED section), `decision-log.md`, `learnings.md` (candidate rows) |
| `ai-pipeline-green-code` | `handoff.md` (GREEN section), `decision-log.md`, `learnings.md` (candidate rows) |
| `ai-pipeline-refactor` | `handoff.md` (REFACTOR section), `decision-log.md`, `learnings.md` (candidate rows) |
| `ai-pipeline-quality-gate` | `quality-gates.md`, `handoff.md` (VERIFY section), `decision-log.md`, `learnings.md` (status curation) |
